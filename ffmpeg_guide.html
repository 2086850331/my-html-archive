📷 Camera 拉起画面，FFmpeg 未推流至外网排查指南

当遇到 Camera 画面已拉起，但 FFmpeg 未能成功将视频流推送到外网时，请按照以下步骤进行排查和修复。

1. 检查正在运行的 FFmpeg 进程

查看当前正在运行的 FFmpeg 进程，确认它们捕获的窗口标题是哪些。在 CMD 中执行以下命令：

wmic process where "name='ffmpeg.exe'" get commandline

或者使用 PowerShell：

Get-CimInstance Win32_Process -Filter "name='ffmpeg.exe'" | Select-Object -ExpandProperty CommandLine

2. 手动测试推流 (GDI 窗口捕获方式)

找到缺少的窗口，在 FFmpeg 的 bin 目录下执行命令：

cd /d "D:\Program Files (x86)\CameraMultipleFormsPlaySystem_Nginx\ffmpeg-4.3.1-win64-static\bin"

示例配置（JSON 格式）：

{
  "TitleName": "121.202.135.136",
  "Ip": "121.202.135.136",
  "LoginAccount": "admin",
  "LoginPassword": "a35683333@",
  "Port": "8000",
  "Channel": "33",
  "CameraCode": "CAR05"
}

执行推流命令：

ffmpeg -f gdigrab -i title="{121.202.135.136}" -tune:v zerolatency -s 1280x720 -c:v libx264 -preset veryfast -maxrate 3000k -bufsize 2000k -pix_fmt yuv420p -g 30 -keyint_min 2 -f flv rtmp://192.168.1.100:1935/live/CAR05

执行后，如果窗口正常，就会开始推流，进程列表里就会多出一个 ffmpeg.exe。

⚠️ 注意 如报错 Invalid properties, aborting，请改用 RTSP 直接推流。

3. 改用 RTSP 直接推流

3.1 确认 RTSP 地址格式

rtsp://用户名:密码@IP:端口/Streaming/Channels/通道号

原始 RTSP 地址示例：

rtsp://admin:a35683333@121.202.135.136:554/Streaming/Channels/3301

3.2 手动测试 RTSP 推流

在 CMD 中进入 ffmpeg 目录，执行：

ffmpeg -rtsp_transport tcp -i "rtsp://admin:a35683333@121.202.135.136:554/Streaming/Channels/3301" -c:v libx264 -preset veryfast -maxrate 3000k -bufsize 2000k -pix_fmt yuv420p -g 30 -c:a aac -f flv rtmp://192.168.1.100:1935/live/CAR05
❌ 报错分析：401 Unauthorized / 404 Not Found 如果在执行上述命令时遇到 401 Unauthorized 或 404 Not Found 错误，通常是密码中的特殊字符和 RTSP 地址的通道号规则问题：
  1. 密码特殊字符问题： a35683333@ 末尾的 @ 符号在 URL 中具有特殊含义（用于分隔用户名和主机地址）。如果不对它进行 URL 编码，设备就会误以为 @ 后面的内容是主机地址，导致认证失败。
    解决方案： 将 @ 替换为 %40。
  2. 海康 NVR 通道号规则问题： 海康 NVR 的 RTSP 通道号并非总是与物理端口号直接对应。对于32路及以下的 NVR，其 IP 通道通常从 33 开始编号。这意味着，如果你的 Channel 配置为 33，它很可能对应的是 NVR 上的第 1 个 IP 通道。那么，这个通道对应的正确 RTSP 地址应该是 101（主码流）或 102（子码流），而不是 3301。
✅ 修正执行命令（成功推流）

结合上述两点修正后，执行以下命令即可成功推流：

ffmpeg -rtsp_transport tcp -i "rtsp://admin:a35683333%40@121.202.135.136:554/Streaming/Channels/101" -c:v libx264 -preset veryfast -maxrate 3000k -bufsize 2000k -pix_fmt yuv420p -g 30 -c:a aac -f flv rtmp://192.168.1.100:1935/live/CAR05
