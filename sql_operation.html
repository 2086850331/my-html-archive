👥 SNR 地盘开工人数 - 补出入口数据 4 步
用途：补录员工进出记录，用于看板统计当日开工人数。适用于读卡器故障或数据丢失时的补录场景。
执行顺序： ①统计当日开工人数 → ②查询公司 ID → ③获取公司员工 → ④插入出入口数据
注意：插入前务必先执行第①步核对人数，避免重复录入。
① 统计当日各判头开工人数 
-- 统计指定日期的开工人数（按判头分组）
-- 结果用于核对补录前后的数据差异
SELECT  *
FROM    (
    SELECT  c.F_ContractorId,
            c.F_EnShortName AS F_ContractorEnName,
            c.F_CnShortName AS F_ContractorCnName,
            c.F_StandardColor,
            c.F_LastWeekColor,
            c.F_ThisWeekColor,
            COUNT(t.F_UserRFIDId) AS F_NumberOfPeople
    FROM    (
        SELECT  CONVERT(VARCHAR(10), t.F_PairTime, 120) AS F_PairTime,
                t.F_UserRFIDId,
                uf.F_ContractorId
        FROM    TB_UserRFIDInOutRecord t
                LEFT JOIN dbo.TB_UserRFID uf ON t.F_UserRFIDId = uf.F_UserRFIDId
        WHERE   uf.F_ContractorId IS NOT NULL
                AND uf.F_DeleteMark = 0
                AND t.F_PairTime >= '2026-10-15 00:00:00'
                AND t.F_PairTime <  '2026-10-15 23:59:59'
        GROUP BY CONVERT(VARCHAR(10), t.F_PairTime, 120),
                 t.F_UserRFIDId,
                 uf.F_ContractorId
    ) t
    LEFT JOIN dbo.TB_Contractor c ON t.F_ContractorId = c.F_ContractorId
    WHERE   c.F_IsShowDashboardMark = 1
    GROUP BY c.F_ContractorId,
             c.F_EnShortName,
             c.F_CnShortName,
             c.F_StandardColor,
             c.F_LastWeekColor,
             c.F_ThisWeekColor
) t
ORDER BY t.F_ContractorEnName, t.F_ContractorCnName;

⚡ SQL Server 性能诊断 3 步
用途：排查数据库性能问题，定位阻塞源、清理执行计划缓存、检查磁盘 IO 延迟。
执行顺序： ①查看活动进程 → ②定位阻塞根源 → ③检查 IO 延迟
注意：KILL 会强制中断会话，执行前请确认 SPID 无误；DBCC FREEPROCCACHE 会清空所有缓存执行计划，可能导致短时性能下降。
① 查看当前活动进程 
-- 查看当前正在运行、占用资源或被阻塞的进程
SELECT
    r.session_id       AS [会话ID],
    r.status           AS [状态],
    r.command          AS [命令],
    r.cpu_time         AS [CPU时间(ms)],
    r.total_elapsed_time AS [已耗时(ms)],
    s.host_name        AS [客户端机器],
    s.program_name     AS [程序名],
    t.text             AS [正在执行的SQL语句]
FROM sys.dm_exec_requests r
JOIN sys.dm_exec_sessions s ON r.session_id = s.session_id
CROSS APPLY sys.dm_exec_sql_text(r.sql_handle) t
WHERE r.session_id > 50 AND r.session_id <> @@SPID;
② 定位"根源阻塞者" 
-- 找出真正的阻塞源头（Head Blocker）
SELECT
    blocking_session_id AS [被阻塞的SPID],
    session_id          AS [正在阻塞别人的SPID(根源)],
    wait_duration_ms    AS [等待时间ms],
    wait_type           AS [等待类型]
FROM sys.dm_os_waiting_tasks
WHERE blocking_session_id IS NOT NULL;

③ 检查磁盘 IO 延迟 
-- 检查数据库文件的读/写平均延迟（毫秒）
-- 正常值：读 < 10ms，写 < 5ms；持续偏高说明磁盘瓶颈
SELECT
    vfs.database_id,
    mf.name AS [逻辑文件名],
    vfs.io_stall_read_ms / NULLIF(vfs.num_of_reads, 0)  AS [平均读延迟(ms)],
    vfs.io_stall_write_ms / NULLIF(vfs.num_of_writes, 0) AS [平均写延迟(ms)]
FROM sys.dm_io_virtual_file_stats(NULL, NULL) vfs
JOIN sys.master_files mf
    ON vfs.database_id = mf.database_id
   AND vfs.file_id = mf.file_id;

-- 4. 验证行数是否一致
DECLARE @oldCount INT, @newCount INT;
SELECT @oldCount = COUNT(*) FROM [dbo].[LR_Base_Module];
SELECT @newCount = COUNT(*) FROM [dbo].[LR_Base_Module_NEW];

IF @oldCount <> @newCount
BEGIN
    PRINT '行数不一致，已回滚！';
    ROLLBACK TRAN;
END
ELSE
BEGIN
    PRINT '行数一致，提交事务。';
    COMMIT TRAN;
END
